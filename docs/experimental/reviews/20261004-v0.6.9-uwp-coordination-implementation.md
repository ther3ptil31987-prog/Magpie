## 窗口协作与首次显示

`SourceWindowCoordinator` 分别记录捕获 HWND 和经过校验的 GA_ROOT 协作目标，没有改变 WGC CreateForWindow 的捕获对象或裁剪。PID／TID、类标识、样式及源监听代次用于复核；源死亡锁存后，即使数值 HWND 有效也不会自动重新接管。绑定数据保留到后端 join 完成，死亡标记为原子状态。

创建、捕获初始化及首帧准备保持无 owner。首次有效呈现后重新核实身份、状态和完整性级别，再读取原始 API 结果、系统错误和实际关系。实际 owner 正确才进入 `NativeOwned`；结构有效、错误 87、owner 为空、权限检查通过且控制器已准备时才进入 `ManagedUnowned`。权限拒绝、未知／零错误、失效窗口、子输出、自身／循环或意外关联继续失败。

兼容模式只安排本进程输出，不移动外部前台／源来模拟 owner。是否置顶与相对层级分开判断，置顶标志不变也能修正位置；变更时回读样式并有限重试。两个 popup 调用点共用 `SourceWindowRelations`，区分自身与真实弹窗，排除输出及其辅助窗。窗口过程在管理模式下不覆盖控制器选定的位置；先排好层级再以 SWP_NOZORDER 显示，失败不弹启动成功 Toast。正常原生 owner 路径保留原窗口协作逻辑。

有限的 out-of-context WinEvent 回调只记录状态并唤醒消息泵。250 ms 核对及生产 PollSourceState 无须新画面即可隐藏／退役输出，沿用现有等待／重建规则；监听在重建等待期间保留。WGC Closed 使用每个 capture item 的共享信号，晚到关闭只触及旧对象；后端消息等待可被唤醒，旧会话错误回调仍受代次保护。

## 停止顺序与资源保留

原先 BeginShutdown 包含 Reflex 配置锁和驱动调用，部分入口早于解除 owner。现在该函数只执行原子取消、禁止新同步呈现和事件唤醒，Reflex Stop 留在 Renderer 析构。CursorManager 的 BeginShutdown 也只请求停止；参数输入的焦点／窗口操作放在核实解除后，解除失败则延后到输出销毁完成后。

Destroy、系统 WM_DESTROY、初始化失败、参数重建和模式切换共享 retirement。旧 Renderer、光标、捕获、swap chain、GPU 纹理与参数状态在销毁回调期间保持存活；回调不 join、不关闭 SDK。WindowBaseT 清空 Handle 后仍保存旧 HWND，保留 userdata 对象身份到内核删除窗口，等待 WM_NCDESTROY 且窗口实际不存在或确已属于其他对象。回调返回后的消息泵／Destroy 才完成清理，避免用回调中的空 Handle 或提前清空 userdata 当作完成证据。

真实解除失败也走同一销毁路径，随后在旧外部 owner 图已切断的状态下清理光标、停止 Reflex、等待后端、关闭 SDK、读取 Applied 参数并保存。旧会话完成前不启动新会话，重入保护保证一次清理／快照交接。边框辅助 HWND 在 USER32 随 owner 销毁后释放包装，避免再次 DestroyWindow。触控孔窗口实际无 owner，源退场时显式隐藏，退役完成时独立销毁；该行为有隐藏及销毁回归。输入和排队的 PrintScreen 回调补充停止／代次检查。

资源安全的源码依据是：取消先禁止新的前端呈现及旧会话回调，资源与 options 在 join 前不释放／替换；后端按既有停止检查退出，相关 D3D／SDK 对象保持到其工作退出。测试证明 CPU／窗口生命周期顺序，真实 GPU／呈现资源验收仍待 T06–T08，不宣称消除所有驱动阻塞。
