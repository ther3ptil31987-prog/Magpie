# RTSS 配置保存失败修复与交接

日期：2026-10-09。分支：`feature/069-rtss-target-frame-rate`，修复基线 `58edd39c`。

普通 FPS 配置的保存与恢复已修复。Apply 和 Restore 共用按当前值设置的方法，避免将已是 0 的 `FrametimeLimit` 再传给拒绝该值的 RTSS setter；实际变化仍检查返回值和立即读回。使用本机 RTSS 7.3.5.28314 DLL 的隔离副本，Global、已有目标、新建目标与小数 FPS 原值的完整保存、读回、重载请求和恢复通过。

产品编译部署与目标应用实测交给独立会话。此次只编译隔离测试程序与测试 PRI；未更新运行包，也未修改用户现有 RTSS 配置。

## 实现

[RtssProfileAccess](../../../src/Magpie/RtssProfileAccess.cpp)保留公开接口写入。相同值跳过 setter，不同值必须设置成功且读回一致。正常 FPS 的原帧时间为 0，Apply 与 Restore 均保持它；新建目标仍设置 Low，已有检测级别与其他字段仍核对。第一次写入前的快照、取消检查、外部修改保护、原分母与表达检查沿用原设计。

失败按读取、属性设置、保存、核对、重载、恢复、冲突及取消分类。SDK 的 Save/Update 为 void，保存后先核对，再发出重载请求；无操作的 Save、部分保存、缺失目标、坏配置和原生接口异常均有独立回归。发生保存尝试但读回不完整时，会话仍保留必要的原值及清理状态；真正停止只尝试一次。

状态说明新增“设置帧率失败”“核对配置失败”“重载配置失败”“无法切换帧时间模式”，20 份资源采用相同键，简体中文与英文完整，其余语言沿用英文回退。日志包含失败阶段、配置对象、版本、属性、请求值、读取值及有效性、saveAttempted、readbackComplete、nativeFault 与文件错误码。文件读取通过 Win32 API 捕获对应错误码；SDK 的 BOOL 拒绝不使用 GetLastError。Apply/Restore 在设置前只打开已有文件或目录核对当前调用者的写入权限，不创建探测文件；访问被拒绝时显示现有权限文案，并记录错误码。

停止处理开始时清空前次失败说明，避免“已保留”或“已恢复”继续显示旧的写入错误。界面布局、手动数值范围和同步显示规则未改动。

## 接口兼容边界

7.3.5.28314 仍拒绝将非零 FrametimeLimit 改成 0。隔离测试能将正 FramerateLimit 与非零 FrametimeLimit 同时保存和重新加载，因而正 FPS 字段本身不能证明已退出帧时间模式；当前不采用保留帧时间的转换方案。此类 Apply 在保存前显示具体原因，且不标记为已应用 FPS。逆向恢复原非零帧时间及分母已分别验证，不能据此声称前向转换可用。

部分原配置省略限帧字段时，SDK Save 会补入字段。已验证该场景可设置整数 FPS，但恢复后的表达缺失关系改变会报告 `RestoreExpressionChanged`，不把近似表达标记为精确恢复。后续字段级兼容设计见[帧时间配置兼容方案](../design/20261009-rtss-time-mode-compatibility-plan.md)。

本机另有独立的权限限制：普通用户对安装目录 Profiles 与 Global 仅有读取权限。使用当前非管理员进程打开 Global 请求 GENERIC_WRITE，或打开已有 Profiles 请求 FILE_ADD_FILE，均返回 ERROR_ACCESS_DENIED（5），未写入任何内容。普通进程因而不能保存全局或新建目标；以管理员身份运行喜鹊主程序，或使用已授予写入权限的 RTSS 安装目录，才具备当前接口路径所需权限。仅管理员身份运行 RTSS/MSI Afterburner，不会改变调用 DLL 的喜鹊进程令牌；本轮没有请求提权或改动 ACL。

隔离目录可写，55 项原生成功不能代替上述安装目录权限验收。按需提权写入或借用现有受信任进程的接入列为 C03，不能以设置跳过修复已经解决权限问题来交接。

最低支持版本仍以实际能力与逐版本事务验证为准，本轮原生结果仅覆盖上述本机版本。UpdateProfiles 已实际调用，其返回无异常只证明请求完成；目标进程的实际限帧效果仍需测量。
