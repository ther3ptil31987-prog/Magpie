## 已实施的变化

| 范围 | 修改与作用 | 保留的行为 |
| --- | --- | --- |
| 前台 API 热路径 | Off／Reference 在构建快照前快速返回；普通非目标调用只读取模块范围及小头部；相同的完整 HWND／PID／TID／class 身份只检查一次 | UWP 双身份仍分别校验；隐藏／最小化、真实源前台、epoch／版本、退休、LastError 保护保留。二次真实前台读取之后再次验证发布版本 |
| 诊断成本 | 默认完整 VRR 停止逐次目标／覆盖计数、调用点记录及 phase 更新；Trace／Profile／性能诊断显式启用。已观察 phase 先 load，首次观察才做 RMW | 未知调用点仍有 16 个有界观察槽和 64 个记录槽；未知模块不获得覆盖资格。查询统计关闭时，日志中的零值表示未采样，结合 `diagnostics` 判断 |
| 发布快照 | 热结构只含源／根／输出身份、5 个目标范围及资格；主界面／参数宿主身份用于冷诊断。字段相同不发布 | 保持逐 word 顺序一致原子操作、单一前端写者、有限读取、版本变化时返回真实前台；没有改成裸结构 seqlock 或无界重试 |
| 模块发现 | 缓存进程内 PIN 的精确模块范围；直接查找未命中的 5 个名称，替代全进程 Toolhelp 枚举与重复 PIN | Prepare、Device 与呈现资格转换立即发现；缺失模块每 5 秒重试。已经 PIN 的范围跨缩放会话复用；不增加 D3D12／叠加层模块范围 |
| 输出资格 | 缓存固定适配器属性和输出归属；几何、远程会话、factory 当前状态仍每 500ms 检查；同屏移动不重复枚举，稳定输出归属每 5 秒恢复探测 | 移动使下次呈现立即检查；Resize 保留强制检查；显示变化消息只使缓存失效，枚举在下一次呈现执行。跨屏、跨适配器、跨屏覆盖、旧拓扑均仍撤销资格 |
| 前端身份采样 | 参数宿主句柄变化时登记身份，复用 `_UpdateSrcState` 已读取的真实前台，移除参数更新之前未使用的前台读取 | 参数编辑／焦点交接继续暂停覆盖；实际业务焦点仍读原 API。冷身份使用前仍检查 HWND／PID／TID／class |
| 画面复制 | `_CopySceneToTarget` 完整复制路径不再先清空相同目标纹理，减少一条随后完全被覆盖的 GPU 指令 | 区域复制仍清空背景、保留黑边；透明独立叠加层仍保留清空。效果链、FG 输入、FIFO、现有限帧和 GPU 等待策略保持原语义 |

Windows x64 布局推导：热查询结构为 **192 字节／24 个原子 word**，冷身份为 48 字节；旧全结构为 288 字节／36 个 word。普通源与 root、输出与 root 都为相同完整身份时，覆盖判定中的身份／状态 API 从 **19 次降至 13 次**；UWP 双源身份仍为 16 次。数值来自结构／源码分析，不是 CPU 耗时测量；C++ 布局及行为断言交给后续编译执行。

缓存模块的 lifetime 依据 [Microsoft 的 PIN 语义](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandleexw)，范围使用 [K32GetModuleInformation](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getmoduleinformation) 读取。Factory 的 [IsCurrent](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgifactory1-iscurrent) 仍按原频率检查，旧 factory 需要按现有会话策略重建；缓存没有把旧拓扑重新判为合格。

## 后续实测的诊断入口

以下是下一会话启动 Magpie 前可选的**进程环境值**；本轮没有设置它们或重启应用。现有进程继承的环境不会随另一终端的变量自动改变，每组必须明确记录实际启动环境。

| `MAGPIE_GSYNC_DIAGNOSTIC` | VRR 开启时的前台层 | 查询观测 |
| --- | --- | --- |
| 未设置 | 完整覆盖 | 默认关闭详细统计 |
| `standard` | 仅标准 DXGI 合同 | 不安装本会话的前台覆盖 Hook |
| `trace` | 真实前台 passthrough | 记录目标及未知调用、phase、角色、计数 |
| `profile` | 完整覆盖 | 记录同上详细诊断；用于完整覆盖与 Trace 的对照 |
| `reference` | 保留原有 10 秒真实前台参考 | 仅用于现有功能参考，不列为稳定 GPU 性能基线 |

额外设置 **`MAGPIE_VRR_PERFORMANCE=1`** 可在普通 Release 中开启工作量诊断；同时打开该会话的查询观测，VRR 关闭／Standard 模式也可记录渲染工作量。默认关闭，每个事件仅检查开关；启用后使用有界原子计数，不在逐帧路径分配／格式化／写文件。每约 5 秒及后端退出后输出一次 `VRR performance:` 聚合行。

| 日志字段 | 含义 |
| --- | --- |
| `epoch requested mode diagnostics presenter multiplier windowMs final` | 会话、VRR 请求、前台模式、是否统计、输出路径／倍率、该采样区间长度、结束采样 |
| `capture effectExecute effectReuse` | 接受的捕获数量、执行／复用的效果节点数量；节点数量不是 GPU pass 数量 |
| `realPublication generatedPublication` | 成功发布到前端的基础／应用生成帧数量；XeSS 的 SDK 内部生成帧不在应用发布队列内 |
| `realSubmit generatedSubmit auxiliarySubmit independentOverlaySubmit failedSubmit` | 前端内容、应用生成帧、复用稳定画面、XeSS 独立叠加层的提交结果；独立叠加层与内容提交分别统计 |
| `fullSceneCopy regionSceneCopy targetClear stableCopy overlayDraw cursorDraw` | 本次接入的前端复制、清空、绘制入口调用数，含随后失败的提交工作；不是完整 GPU 指令、字节数或全部 SDK／DWM 工作 |
| `presentCall tearingPresentCall presentCpuNs` | 共享最终 DXGI／代理 Present 调用次数、tearing 调用次数及 CPU wall time 总和；普通失败后安全重试分别计数，XeSS 不重试输入 |
| `auxCursorDirty auxPanelDirty auxInputDirty auxBackgroundDirty auxUnclassified` | 绘制前采样的辅助提交原因，可同时命中多个原因；未分类包含强制／可见性／最低刷新等未单列原因，不代表无意义重绘 |
| `reportedFrames reportedFrameSamples` | Presenter／SDK 返回的数量与有效样本数，未知返回不计；不替代实际显示帧率，独立叠加层不计入此字段 |

所有工作量字段都是 `windowMs` 区间内的增量；`数量 × 1000 / windowMs` 为该区间的调用／提交率。`presentCpuNs / presentCall` 是 CPU 平均 Present 耗时。前端与后端计数读取不构成同一帧的原子事务，边界可能有少量跨窗偏移；不跨 epoch 相减。

日志明确写 `gpuTiming=unmeasured displayFrames=unmeasured`。实际 GPU busy／每帧 GPU 时间、引擎归属、频率／功耗、显示率和指示器另行记录。诊断模式也有成本，先测默认关闭诊断的自然表现，再使用同一诊断设置比较工作量；开启 Trace 与完整覆盖后的 G-SYNC 状态可能不同，需一并记录。
