# 0.6.7 错误引导改动与验收

基准为 `ac1cc8b0`，工作分支为 `0.6.7`。下面记录本轮实现范围和验收边界；自动化测试通过不代表已完成真实 GPU 或界面故障复现。

## 前后行为

| 场景 | 修改前的问题 | 本轮行为 |
| --- | --- | --- |
| 捕获失败 | 建议选择不存在的“默认”；已经使用 Graphics Capture 时仍建议同一选项 | 按当前捕获方式给出步骤，详情带窗口、配置和捕获阶段，可打开对应配置 |
| 窗口模式限制 | 说明限制，但包含错误选项名称 | 指向 Graphics Capture 或 3D 游戏模式设置，并给出主页全屏模式快捷键作为替代入口 |
| 效果组未选、为空 | “当前配置”不能定位到自动匹配的实际对象 | 显示配置名和效果组名，提供配置或效果组页面入口 |
| 未知效果器、补帧冲突 | 泛指未知或冲突项 | 详情列出实际效果器序号和名称，进入效果组页面处理 |
| VSR 错误 -2 | 将路径视作已经确定的原因，强调禁止字符 | 给出完整解压到示例目录并重试的步骤，明确路径兼容性仅为可能原因 |
| 原生 AI 效果初始化 | 底层失败信息被压缩成通用错误 | 收集本次初始化的错误日志与系统码，保留相关 GPU、驱动及图像尺寸；DLSSNR 降级说明对应处理状态 |
| 光流失败 | 无法知道哪些效果器受影响 | 列出受影响消费者及请求方法、质量，步骤使用相关参数和选项名称 |
| GPU 同步失败 | 单显示卡用户被引导到隐藏的切卡设置 | 多卡与单卡分别生成步骤，只有多卡才建议打开“性能 → 显示卡” |
| 启动配置读取、备份失败 | 只有退出按钮，或仅日志 | 启动对话框显示实际位置、系统码和步骤，提供打开目录与复制详情 |
| 配置损坏后恢复 | 设置发生变化而没有解释 | 区分备份恢复、部分恢复，保留损坏原件位置；恢复通知不覆盖未保存警告 |
| 配置保存失败 | 依赖再改一个设置来重试 | 详情提供“重试保存”，保存当前配置且无需重启效果组；明确成功或仍失败 |
| 参数保存、会话、实时应用失败 | 单行短句未说明恢复方法 | 指明画面与保存状态及下一步；底部错误区域支持换行、滚动，详情保留完整步骤 |
| 导入格式错误 | 告诉用户改扩展名无效 | 指向导出方的 Magpie“效果组 → 导出”流程；结构原因和文件位置留在详情 |
| 截图编码失败 | 要求选择 PNG，但实际没有格式选择器 | 区分中间 DDS 与当前画面 PNG，指向实际工具栏“截图”按钮 |

短提示显示具体问题或第一步，完整处理步骤留在主页问题卡和详情。最近一条诊断写入配置目录的 `last-issue.json`，关闭问题卡后可重新打开。重启后标记为上次运行记录，相关旧会话操作不自动重放。

## 自动化覆盖

- `scripts/tests/config_persistence_retry.cpp`：在独立目录制造 Windows 文件占用和只读目标；确认失败保留原配置、解除限制后可直接重试、旧异步版本不会覆盖新版本；检查损坏配置的完整项恢复及有效备份保留。
- `scripts/tests/error_guidance.cpp`：覆盖捕获方式与 GPU 数量边界、读取和写入失败建议的区分、对应处理入口、恢复通知以及未知错误回退；验证保存结果乱序到达、重复失败与再次成功，以及保留无关新问题。
- `scripts/tests/test_capture_shutdown.py`：从生产代码生成 CPU 测试程序，覆盖捕获回调清理顺序及带上下文的回调在会话清理期间仍有效，包含 1,000 次重启循环。
- `tests/consistency/run.py`：检查资源和仓库约定。既有警告须与基准比较，不以警告总数代替结论。
- 三语言文案检查：本轮变动键在简体中文、繁体中文、英文中均存在且非空，运行时格式占位符一致。
- Windows x64 Release 全解决方案编译：包括主界面生成代码及当前本机已启用的原生效果后端。

原生测试使用 C++20、MSVC 和项目已有依赖，须启用断言（不定义 `NDEBUG`）。配置测试要求传入独立测试目录，程序会创建带进程号的子目录；不要传入用户真实配置目录。捕获测试使用 Python 生成测试源码，再按脚本说明编译运行。

本机验证结果（2026-09-08）：上述配置持久化、引导策略与保存乱序测试通过；捕获测试通过 12 个场景、1,000 次重启循环及 8 个集成顺序检查。60 个变动资源键三语言检查通过。一致性检查为 `FAIL=0 WARN=22 INFO=358`，警告数与改动前一致。完整 x64 Release 编译及最终增量构建均以退出码 0 完成，产物在隔离目录 `bin/x64/0.6.7-guidance/`；首次完整构建有外部 FSR SDK 的既有结构对齐警告。本次未启动新构建进行真实界面或 GPU 故障测试。

## 真实界面与硬件验收清单

以下项目仍需在隔离配置和对应硬件上实际操作。每次记录构建版本、GPU、驱动、捕获方式、语言，以及问题详情和截图。

| 复现 | 应检查的用户结果 |
| --- | --- |
| 分别以 Graphics Capture 和其他方式触发捕获失败 | 建议符合当前值；“打开此配置”定位正确；配置删除或重命名后提供返回配置列表的步骤 |
| 单卡、多卡环境触发同步失败 | 单卡没有切卡建议；多卡提示与实际显示卡入口一致 |
| 多个效果器共享失败的光流提供器 | 详情列出所有相关消费者，参数步骤能在各效果器内找到 |
| 原生 SDK、模型或设备初始化失败 | 详情对应本次失败阶段，未将未确认原因描述为定论；DLSSNR 降级说明与画面一致 |
| 启动时配置不可读或损坏原件无法备份 | 主窗口创建前即可打开目录、复制诊断；操作失败仍显示可手动使用的路径 |
| 从备份恢复、部分恢复，以及恢复后保存失败 | 清楚说明来源与损坏原件位置；优先保留未保存状态 |
| 参数保存失败后解除文件占用，连续重试 | 无需再改参数或重启效果组；失败可再次重试；成功状态正确；期间的新问题不被旧回调清除 |
| 详情打开期间关闭对话框、结束效果组或提交新修改 | 异步回调不访问已销毁的控件，较旧保存结果不覆盖新问题 |
| 窄参数面板、125% 至 200% 缩放、三种语言 | 长恢复步骤可以换行或滚动读完，按钮名称与实际控件一致 |
| PNG、DDS 编码失败以及截图写入失败 | 编码与写入建议区分，均指向真实存在的操作入口 |
| 关闭问题卡、退出并重开应用 | 最近记录可再次查看，上次运行标识清楚，不执行旧会话补救操作 |

本轮诊断记录仅保留最近一条，不能用作完整事件历史。效果组按钮进入效果组页面；具体组名和问题项由详情提供。
