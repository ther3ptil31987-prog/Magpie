# RTSS 帧时间配置与原表达兼容方案

日期：2026-10-09。Magpie 初始化的两个限制清零入口已按此方案完成，见[实施记录](../reviews/20261009-rtss-status-magpie-init-and-admin.md)。Global/目标转正 FPS 和缺失字段恢复仍待后续兼容实现，继续使用公开接口写入。

本机 RTSS 7.3.5.28314 可以读出 FrametimeLimit=0，但 setter 拒绝该值。非零帧时间因而无法通过已验证接口清零；同时保存正 FPS 和非零帧时间也不能证明模式已切换。当前实现对此报告“无法切换帧时间模式”，普通 FPS 配置已通过相同值跳过规则完成保存与恢复。

另一个兼容场景是部分原配置省略限帧字段：SDK Save 会补入字段，恢复值后仍可能改变原来的缺失关系。字段级写入若采用，应同时解决这两个具体场景。

## 入口与字段范围

按实际可解析的配置结构、当前表达和所需读回能力判断文件兼容路径，不以版本号作为门槛。API 明确不能完成所需表达变更时，只有相应字段路径能够保留原内容并完成验证才使用该路径。权限、接口异常、一般 Set 拒绝或读回失败不自动触发文件回退。范围仍来自用户选择的 Global 或目标 exe，不按 HWND 或 DLL 内部地址操作。

只允许编辑 `[Framerate]` 下的 `Limit`、`LimitDenominator`、`LimitTime`、`LimitTimeDenominator`。应用整数 FPS 时写入整数上限、FPS 分母 1 与帧时间 0，保留原帧时间分母；恢复时按快照还原四项的值、文本精度和字段是否存在。其他字段、节顺序、注释、编码和换行保留。

已有独立配置只编辑对应文件。新建目标仍需继承 Global 并设置 Low，公开接口创建与字段级转换必须组成同一受控事务；创建/设置阶段失败时记录实际落盘，不把未验证的文件认作可删除对象。

## 写入与竞争

在同一 RTSS worker 内串行。预先解析不超过现有上限的配置，拒绝重复字段、无法识别的编码和无效分母。完成候选字节内容后，重新确认文件身份、完整内容及本次会话有效性；候选只在同目录创建，不从整个旧快照重建用户配置。

采用可保留被替换版本的同卷文件替换，并验证替换结果及被替换版本是否等于刚核对的内容。Windows ReplaceFileW 不提供按内容比较后替换的原子条件：检查与替换之间仍可能发生外部编辑。实现必须识别该窗口，并只在当前内容仍等于本次输出时尝试回退到实际被替换版本；若不能安全处理竞争，停止该次事务。路径串行和替换成功本身不能作为无竞争保证。

写入成功后重新 LoadProfile，核对 API 值与完整磁盘内容，再调用 UpdateProfiles。SDK 不能暴露的字段以磁盘原表达校验，其他字段必须与写入前的当前配置一致。任何失败都保留 saveAttempted、实际读回和清理状态，不掩盖部分写入。

## 恢复与验收

恢复已有配置只在当前限帧状态仍等于本次最后写入时进行，保留当前其他字段。恢复缺失关系时只删除原本缺少的四项限帧字段，不能删除整个节或其他键。新建目标的删除仍要求内容与本次写入完全一致；已被外部修改时保留。停止只尝试一次，不增加持久补偿或自动重试。

实施前需覆盖非零/小数帧时间、缺失键与节、注释/编码/换行、重复键拒绝、共享冲突、权限失败、部分替换、替换窗口中的外部编辑、取消、API/磁盘不一致和重载异常。隔离原生事务通过后，再用目标进程的实测 FPS 验证帧时间到 FPS 的模式切换。

此方案不定义 DLL 内部状态修改，不修改用户现有文件进行试验。对应实现与其他版本验证继续列在[保存失败 TODO](../todos/20261009-rtss-save-failure-TODO.md)的后续兼容项。
