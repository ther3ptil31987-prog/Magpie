## 目标与依据

让不了解算法的用户在读完一项说明后，能够说出“它做什么、画面会怎样变化、适合什么内容、如何开始使用”。每个条目聚焦自身，新旧效果在语气、信息顺序和篇幅上保持一致。

用户指出上一轮仍有三类问题：防御性否定过多；0.6.9 后新加效果的表达未统一；一个效果的说明混入大量其他效果和组合知识。此前的事实修正与自动检查保留，但不能据此宣告本轮用户说明验收完成。

本轮依据为修订后的[效果器说明维护规范](../EFFECT-DESCRIPTION-GUIDE.md)。[上一轮 TODO](20261013-effect-descriptions-and-guidelines-TODO.md)及[审查交接](../reviews/20261013-effect-description-standards.md)保留事实核对、源码修正和测试记录；其中“在叶子中展开完整兼容清单”等表达策略以本轮规范为准。

## 重写原则

| 当前问题 | 后续处理 | 验收重点 |
| --- | --- | --- |
| “不代表／不保证／请比较”反复出现 | 删除无助于决策的防御句；真实取舍用具体作用说明 | 主体是否在讲功能，而非逐条预防误解 |
| VFG、FSR3 FG 等篇幅和层次明显不同 | 统一为作用 → 场景 → 关键用法；必要条件短句收尾 | 与旧效果并排阅读是否像同一套产品文案 |
| Upscale 介绍 VSR／Bicubic，VFG 大讲 TrueHDR，FSR3 列十几个效果 | 可选推荐归分类，完整组合归使用文档，底层算法归开发依据 | 理解当前条目是否需要认识其他效果 |
| 133 项通用 HDR 提醒重复附加 | 逐项判断保留、精简或移出；特殊回退与直接启用条件准确保留 | 不用新的一句通用警告继续批量替换 |
| 参数变更方式、默认值等挤占详情 | 作用与生效条件放参数提示；可见数值交给控件 | 详情聚焦初次选择，提示帮助当前操作 |
| 结构校验通过被当成写作完成 | 先做用户视角阅读评审，再做事实与生成校验 | 能否用简单语言复述用途、场景和起步方法 |

“仅支持 SDR”“固定 2×”等真实使用条件继续准确表达。删除防御语气不等于删除事实，也不采用关键词批量删除。只有当前操作必需的直接依赖才在条目里简短点名；可选组合移出主体。

1. 用户读单个条目即可理解自身用途、适用画面和起步方法，必要条件清楚。
2. 新旧效果的顺序、语气、篇幅尺度一致；比较、组合和技术证据各有合适位置。
3. 删除或移出的是不合适的表达与信息位置；实际能力、关键限制和有效检索入口保持准确。
4. 中英文同步，正式来源与生成产物一致；测试保障事实和结构，不强迫界面保留冗长文案。
