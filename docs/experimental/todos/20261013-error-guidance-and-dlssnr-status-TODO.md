## 3. P2：按证据细分原因并保留未知情况

- [x] 在现有后端结果和错误传递路径中补充必要的结构化失败信息：失败阶段、原因、原始错误码及其类型、实际降级结果。由掌握失败事实的层产生，不让 UI 解析英文日志猜原因。
- [x] 记录实际选中的渲染显卡名称与设备标识、驱动版本、实际 DLL 路径与版本；必要时在诊断中提供文件指纹，不在渲染热路径反复读取文件。
- [x] 保留稳定的现有 MP 编号；新增子原因或编号时不重排旧编号，不把本任务扩展为全项目错误框架重写。

| 待覆盖原因 | 判定边界 | 对应处理方向 |
| --- | --- | --- |
| 当前渲染显卡不满足要求 | 依据实际适配器与已验证支持规则；不能只看显示名称 | 有合适显卡时定位渲染显卡设置，否则说明更换效果器 |
| DLSSNR DLL 缺失 | 确认目标文件不存在 | 打开程序目录，指向当前版本运行文件恢复步骤 |
| DLL 加载失败、依赖异常或接口不完整 | 分开记录加载失败与缺失导出；加载失败不能直接断言主 DLL 缺失 | 展示实际文件和失败类型，指导恢复匹配的运行包 |
| 驱动或运行库版本不满足要求 | 仅在有可靠版本规则和实际检测值时归因到单一组件 | 显示当前版本、要求及适用范围，提供对应更新步骤 |
| 显存不足 | 依据明确的 SDK / 图形 API 结果 | 定位输入分辨率、层数等实际可调设置，并给出重试方式 |
| 访问失败 | 指明具体操作和对象；区分读取、写入、窗口权限查询及真实权限差异 | 提供与该操作相符的恢复建议，避免通用管理员建议 |
| NGX 异常后被保护性禁用 | 依据当前进程故障保护状态 | 明确从托盘完全退出并重新打开 Magpie |
| 功能创建或执行被拒绝，具体原因未确定 | 保留阶段与 SDK 原始结果，不猜测 DLL、驱动或硬件根因 | 显示已有检测事实、最小排查步骤和复制诊断入口 |

- [x] `FeatureNotSupported` 不直接映射为“显卡不支持”；`OutOfDate` 不直接映射为“驱动过旧”，它也可能涉及功能库。
- [x] 区分初始化、运行、尺寸重建失败，保留首次有效失败信息，不让清理错误覆盖它。
- [x] 驱动门槛、DLL 选项和 GPU 匹配规则随已验证的发行组件维护；不要直接把历史指南的固定版本或系列对应关系写成永久判定规则。

依据：[NVIDIA NGX 错误定义](https://raw.githubusercontent.com/NVIDIA/DLSS/main/include/nvsdk_ngx_defs.h)、[Microsoft LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw)。这些通用定义不能单独证明当前 DLSSNR DLL 的硬件兼容范围。

- [x] 能确定目标时，定位实际配置、效果组和效果器；目标已删除或变化时说明情况并提供列表入口，不能误操作其他对象。

- [x] 明确区分重新启用效果组、重启 Magpie、重启 Windows；只有该失败路径需要时才给出相应步骤。
- [x] 错误详情保留可复制的会话、效果器、环境和原始结果；用户无需手动翻译日志才能找到第一步。
- [x] 已知原因优先给针对性操作；未知原因给有限的检查步骤及反馈出口，不堆叠更新驱动、换 DLL、管理员、关闭超频等通用建议。

文案示例仅适用于“已确认 DLL 缺失且当前确实降级继续显示”的场景：

> **DLSSNR 已跳过：缺少运行文件**
> 当前效果组仍在运行，但没有应用 DLSSNR 处理。
> 请完全退出 Magpie，按当前版本的运行文件说明恢复 `nvngx_dlssnr.dll`，然后重新打开 Magpie 并启用效果组。恢复后，此处应显示“运行中”。
> 操作：打开程序目录 / 查看恢复步骤 / 复制诊断。
