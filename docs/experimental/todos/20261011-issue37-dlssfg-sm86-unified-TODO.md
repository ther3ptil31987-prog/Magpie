# DLSSFG 社区兼容版本统一接入 TODO

日期：2026-10-11（Asia/Shanghai）。需求来源：[Magpie Issue 37](https://github.com/SAOG0721/Magpie/issues/37) 及本次需求对齐。

后续实机发现：Beta7 在 RTX 5070 Ti 上启用失败，NGX 返回 `FeatureNotFound`。已确认代理映射与配套库准备是不同阶段；优先执行 [启动失败修复 TODO](20261011-issue37-dlssfg-sm86-startup-failure-TODO.md)，再继续原硬件验收。

状态：已在 `feature/dlssfg-sm86-unified` 写入源码候选和脚本回归；按用户要求未编译、未部署。原 P0 运行继续条件及实机验收仍未通过。逐项源码进展与后续会话要求见 [开发交接](../reviews/20261011-issue37-dlssfg-sm86-implementation.md)。下面未勾选的项目保留原验收含义，不用源码接线替代运行验证。

目标：将喜鹊现有 DLSSFG 默认升级为 dlssg_for_sm86 社区兼容实现。受支持用户更新后通过原入口使用新实现，无需选择库、安装额外兼容包或手动编辑 INI。最高倍率仍为 4×。

## 1 已确定的产品范围

- 保留效果 ID `DLSSFG\DLSS_FrameGeneration`、现有效果组和配置关联，不新增第二个社区版效果器。
- 界面不增加原生与社区库选择。社区兼容实现成为现有 DLSSFG 的默认实现。
- 倍率维持 2×、3×、4×；`MaxGeneratedFrames=3` 表示最多生成 3 张中间帧，加真实帧共 4×。本次不扩展 5×、6×，不实现动态倍率。
- 旧倍率、光流、重复帧过滤和效果链顺序保持原语义。已有 DLSSFG 配置自动沿用新实现；未使用 DLSSFG 的效果组不自动添加补帧。
- 社区内核默认采用 `Optimized=1`。有损档位与实验性加速不作为默认升级行为。
- 接入目标覆盖受支持的 RTX 20、30、40、50 系。实际可用性依据当前渲染设备、驱动、运行库和执行结果判断；不将此功能表述为支持 AMD、Intel 或任意 NVIDIA 显卡。
- 40／50 系也纳入社区路径验收，不将“仍走旧路径但代理已加载”视为完成统一升级。
- 普通用户不承担路由配置。开发诊断可记录或覆盖内部选项，但不形成新的日常操作流程。

- TODO 保存于日常源码 `source/docs/experimental/todos/`。日常源码提交为 `13adddb6816ecf25cc80b043f0b2f9e0351cb297`，存在其他工作留下的未提交修改；实施时重新确认应包含的最新产品修复。
- 上游候选：0.3.5，提交 `9621db573e07ed54f50c15bbb585ed9a7bdfac28`。优先验证根目录的 310.9 配套版本，倍率限制为 4×。
- 已静态检查的上游根目录 `version.dll`：30,021,920 字节，SHA-256 `C3934A09399F022504227C72DF0BF8C0DE55F9A08880DDDDE898C5262CEFA838`。该记录用于复核候选文件，不代表运行验收或签名信任验证通过。
- 上游提供代理、配置及内嵌运行库／后端；公开分支未提供文档所引用的完整 C++ 源码与构建接口。该代理不是可直接改名为 `nvngx_dlssg.dll` 的替代文件。
- Beta6 当前随包 DLSSG 为 `310.7.0.0`；社区后端与自身 310.1／310.9 运行库配套，不能假定能直接适配当前 310.7。
- Magpie 直接调用 NGX D3D12，已有生成、共享资源和呈现链路；此次不引入 Streamline 或另写呈现器。
- RTX 5070 Ti 约 10% 提升来自贡献者自述，4090 多帧成功来自用户报告，均不作为 Magpie 性能达标证据。默认配置在各代显卡上的实际社区路由仍待确认。

- [ ] P0-03 在独立产品副本验证 `Mode=Bundled`、`Optimized=1`、`MaxGeneratedFrames=3`。依次跑通 2×、3×、4× 的直接 NGX 路径，不使用强制增加生成数量的实验补丁。
- [ ] P0-04 确认代理加载时机早于首次相关 NGX 初始化和能力查询。覆盖 DLSS SR 的 D3D11 路径、DLSSNR 与 DLSSFG 共用的 D3D12 Core，避免仅在 FG 创建时加载造成接管过晚。
- [ ] P0-05 确定正式包的自动加载方式。核对现有 `VERSION.dll` 导入入口和显式加载独立目录方案，选择可重复验证、不会要求用户手工安装的方式；不批量放入多个替代代理。
- [ ] P0-06 对 RTX 20、30、40、50 分别确认物理 GPU、运行库重定向、后端 `active` 和实际内核路径。区分 `Router`、`ForceSM86Route`、`SimulateAmpere`、`SpoofArchToGame` 的作用，所需参数由实现内部配置，不能把所有诊断开关统一打开。
- [ ] P0-07 验证不使用 Streamline 时所需的最小架构适配范围；测试关闭游戏侧架构伪装是否可行，保留实际需要的 NGX 适配，不误改 DLSS SR／NR 或其他 NVIDIA 组件的架构判断。
- [ ] P0-08 完成运行证据链：能力可用、Feature 创建、Evaluate 成功、插值禁用状态、有效生成纹理、生成帧实际提交呈现。代理加载、倍率菜单、复制真实帧和 FPS 计数均不能单独作为成功证明。

继续条件：直接 NGX 原型可稳定工作，所选自动加载方式明确，各目标架构的路由有可复核记录。尚未覆盖的硬件保留待验证状态，不以一张卡的结果代替全部架构验收。

## 4 P1 原位接入与效果器门禁

- [ ] P1-01 将已验证的社区运行库加载与状态管理接入现有 DLSSFG，保留效果 ID、配置入口、Frame Guidance、D3D11／D3D12 互操作和 Renderer 呈现链路。
- [ ] P1-02 按进程生命周期管理代理。现有代理没有公开初始化／关闭接口；未证实安全之前不热卸载钩子，也不在同一进程内声称已切回完全未挂钩的原生状态。
- [ ] P1-03 核对能力查询的时序和缓存。保留 `FrameGeneration.Available`、Feature 创建及资源检查；能力为零时记录具体原因，不能直接强改为支持或绕过失败继续执行。
- [ ] P1-04 保留 `min(请求倍率, 实际可用倍率, 4)` 的边界。HLSL、Renderer、生成器的最高 4× 限制和现有容量沿用；覆盖能力查询缺失、零值、超大值及导入非法倍率，避免静默产生错误倍率或越界。
- [ ] P1-05 复查 UI、效果分类、参数解析和后端中的型号／架构限制。本次基线未发现 DLSSFG 的 40／50 系白名单；如实施基线存在过时限制，改为实际能力判定。保留 x64 构建条件、设备／格式条件和同组单一补帧器约束，不波及 VFX 等其他效果的独立门禁。
- [ ] P1-06 按实际渲染适配器的 LUID、PCI 身份和物理架构选择资源与路由，验证混合显卡、手动选卡、切换渲染 GPU 和设备重建；不依赖显示名称或枚举到的第一张 NVIDIA 卡。
- [ ] P1-07 保留旧配置中的倍率、光流和重复帧过滤，更新中英文效果说明与错误提示。缺省参数沿用既有语义，更新后不自动升至 4×。
- [ ] P1-08 覆盖停止、重复启动、Resize、倍率变更、场景切换和 Feature 重建。保持先排空 GPU 工作与呈现任务、再释放和重建资源的顺序，确保旧内核状态不串入新 Feature。
- [ ] P1-09 保留输入帧身份、历史重置、生成帧顺序、插值禁用输出检查及有界队列背压。首帧／重置帧只发布有效内容，工具栏或光标单独刷新不错误推进补帧历史。
- [ ] P1-10 定义失败行为：初始化失败明确报告；运行时失败沿用有界恢复策略，安全时退回真实帧并明确停用 FG，设备或 NGX 状态已损坏时停止会话并提示重启。不能以静默回落掩盖社区路径失效。
- [ ] P1-11 增加运行诊断：GPU LUID／PCI ID／架构、驱动、代理哈希、实际运行库／后端路径与版本、关键路由、请求／有效倍率、Evaluate 与插值状态、生成／真实帧呈现计数。读取不到版本字段时使用包版本与哈希标识，不伪造版本。

## 6 P2 自动回归与实机验收

- [ ] P2-01 自动回归覆盖旧配置迁移、2×／3×／4× 边界、异常能力值、FG 互斥、加载失败、错误传播及更新完整性。复用现有相关测试，不用仅匹配源码字符串的检查代替实际行为验证。
- [ ] P2-02 在 RTX 20、30、40、50 代表硬件上验证 2×／3×／4×。记录型号、驱动、HAGS 状态、输入与输出分辨率、配套文件指纹和实际社区路由。非 NVIDIA／无 FG 场景验证普通功能不受影响。
- [ ] P2-03 对 40／50 系进行同运行库版本、同输入、同分辨率、同倍率的原生／社区对照；另对比旧 Beta6 与完整升级版本，区分运行库升级收益和社区内核差异。
- [ ] P2-04 记录预热后每组 FG GPU 耗时、基础输入帧率、实际生成／呈现数量、输出间隔、显存和长时间稳定性，冷启动与缓存重建单独记录。若测端到端延迟，注明测量方法；不能用 Present 提交时间冒充显示或输入延迟。
- [ ] P2-05 覆盖零运动矢量、AMDOF、NVOF，测试快速运动、遮挡、粒子、细文字、HUD、光标和场景切换。喜鹊仍缺乏游戏原生深度与独立 HUD-less／UI 平面，不能将社区内核接入表述为补齐这些输入。
- [ ] P2-06 验证 SDR 与 HDR 的格式、线性范围、白色亮度归一化、高光及颜色；回归 DLSS SR、DLSSNR、Reflex、RTSS、RTX Video 和各自正常启停。
- [ ] P2-07 验证普通缩放、不使用 FG、切窗口、改尺寸、反复启停、多 GPU 切换和设备故障恢复，特别检查进程级代理对其他效果的影响。
- [ ] P2-08 汇总逐项证据与未覆盖项。所有目标架构的必需验收完成、无未解决的明显性能／画质／稳定性回退、覆盖升级成功后，才将状态改为可发布；构建通过和 DLL 加载成功不等于硬件验收完成。

性能回退的数值判据应根据重复对照的测量波动在测试前确定并记录，不预填“零损耗”或收益百分比。某架构的社区路由未通过时，保留为未完成项并修复，不把默认旧路径当作该架构统一升级完成。
