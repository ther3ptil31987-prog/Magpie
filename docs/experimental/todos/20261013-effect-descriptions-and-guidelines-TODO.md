## 3. 拟加入项目的长期说明规范

已创建[效果器说明维护规范](../EFFECT-DESCRIPTION-GUIDE.md)，并从实验文档索引与中英文贡献指南链接。下表保留规划摘要，正式规则以该规范为准。

| 内容层级 | 要回答的问题 | 规则 |
| --- | --- | --- |
| 摘要 | 做什么，关键区别是什么？ | 一句话；中文通常 20–35 字，以完整表达为先。英文独立组织句子，遵守现有长度检查。仅 SDR、固定倍率等影响能否使用的限制优先保留 |
| 详情 | 适合什么素材，怎么组合，有什么条件？ | 按用途／差异、使用方法、必要限制组织。普通效果几句话，复杂效果分短段，不强制套满所有栏目 |
| 分类说明 | 这一类解决什么问题？ | 给出选择方向和共同约束，避免重复所有效果介绍 |
| 家族／子家族说明 | 各变体怎么选？ | 解释 DN、Soft、RGB、NoJitter、倍率、模型规模等实际差异；型号大、档位高不等于实测画质更好 |
| 相关参数提示 | 增减或切换会怎样，何时生效？ | 使用界面实际名称，说明影响、取舍、适用条件和生效方式；不重复可直接看到的范围、默认值和步进，除非它们影响操作判断 |

通用要求：

- 描述本项目当前实现，不把厂商 SDK 能力直接当成 Magpie 已提供的能力。硬件条件按所选渲染 GPU 和实际运行库核对。
- 必须保留影响选择或操作的限制：输入／输出尺寸和颜色域、硬件、运行库、链顺序、互斥条件、重要副作用；不以精简为由隐藏限制。
- 实现细节只有在帮助用户决策时保留。队列、内部格式、审查过程、旧配置迁移和历史发布内容通常放在开发／迁移记录。
- 区分“实时生效”“重新启动缩放”“重启喜鹊”，与参数页、运行面板及后端实际行为一致。
- 中英文同步核对名称、倍率、默认值、单位、限制和生效语义；统一超分、补帧、光流、采样抖动等术语。
- 效果 ID、显示名和搜索别名分别维护。保留有效旧名与拼写别名，不把整段旧说明不断追加进搜索字段；别名调整应验证既有搜索入口。
- 推荐标签必须有明确依据；高开销不自动等于实验性，“优先尝试”不代表实测最优。没有依据时不写具体收益或硬件支持范围。
- 新增效果或改变已有能力时，同步维护说明来源、相关参数提示和审查记录。记录事实依据对应的源码／运行库版本及未验证边界。
- 保持现有目录结构和生成机制，优先复用检查；不为文案规范额外引入通用框架或无关重构。

摘要风格示例，仅用于确定语气，实施时仍需核对完整条件：

- Nvidia VFX VSR：AI 视频增强，可放大、降噪或去模糊。
- Nvidia VFX Upscale：轻量视频放大，支持固定倍率和自动适配。
- FSR3 FrameGeneration：实验性 2× 补帧，仅支持 SDR。

## 5. 修改入口与验证边界

Beta8 的实际说明来源由 `scripts/Read-EffectCatalogReview.ps1` 合并：

1. `docs/experimental/reviews/20261002-effect-description-review.json`：既有效果与分类／家族说明。
2. `docs/experimental/reviews/20261009-nvidia-vfx-suite-effect-description-review.json`：VFX 替换及新增项。

`scripts/Generate-EffectCatalog.ps1` 生成 `src/Magpie/EffectCatalog/zh-Hans.json`、`en-US.json` 和 `hdr-components.json`；相关参数提示位于语言资源与参数本地化入口。实施时先确认最新合并关系，不覆盖日常主目录保留的旧修改，也不只改生成 JSON。

验收完成条件：

- 全部当前内置效果和各级说明有审查状态；关键问题有处理结论，中英文事实一致。
- 用户可以据说明判断用途、必要条件、变体差异和可用组合；关键操作不依赖猜测或不存在的列表。
- 重新生成不会丢失修订；ID、分类关系、旧别名、相关参数语义及源码依据可核对。
- 规范能够指导后续新增／变更效果，并已接入项目维护入口。
- 静态／自动验证、真实界面和 GPU 画质／性能分别记录。文案工作不新增画质、帧率或延迟收益承诺；产品构建部署和实机工作需在后续执行范围中明确安排。
