## 1. 从必要条件推导方案

参数面板要接收普通键盘数值输入，就需要正确的本线程焦点和消息接收窗口。源游戏与独立参数宿主不能同时占有同一份真实前台输入。当前宿主进入前台后，源游戏确实会失焦；Magpie 将宿主视为内部窗口，只能维持自己的缩放会话，不能改变游戏收到的失焦通知或后台策略。微软说明 `SetForegroundWindow` 会改变前台及键盘输入方向，而且系统可以拒绝该请求。见 [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

因此，“会话继续”“游戏真实前台”“参数持有输入”必须分别表达。单独放宽窗口白名单、扩大稳定期或反复设置前台，都不能保证游戏不暂停，也不能保证后台原始输入不会继续触发游戏操作。

| 必须满足的条件 | 推导出的实现约束 |
| --- | --- |
| 捕获目标正确 | 捕获 HWND 和裁剪保持原值；用于激活的已校验顶级根窗口独立保存，不能为了焦点修复更换捕获对象 |
| 前台事实可信 | Windows 真实前台与本线程键盘焦点是事实输入；逻辑会话状态及未来驱动兼容实验不得覆盖这些事实 |
| 输入归属明确 | 一次正常交互的按下／重复／松开由同一输入路径收尾；交接中不让尾部消息落进游戏或新会话 |
| 仅响应当前用户意图 | 按钮、快捷键、预览点击可以请求编辑；异步回调必须重新检查源身份、前台、生命周期及待执行意图 |
| 会话不会因内部交接误停 | 经验证的源／根窗口和参数宿主使用一致身份分类；输出窗口仅在规定的过渡条件下放行 |
| 外部应用与源弹窗获得正常控制 | 切出、模态弹窗或源失效取消参数接管；禁止从旧会话自动激活到其他应用之上 |
| 层级与输入区域一致 | 输入宿主随输出可见性、实际置顶状态和最后成功呈现的区域更新，不能留下覆盖其他窗口的透明点击层 |
| 内容时间轴准确 | 参数、工具栏和光标刷新可以使用缓存背景；它们不等同于新捕获帧，不推进 NR／FG 内容历史 |
| 停止能够完成 | 正常交接等待完整输入；外部失焦和源退役使用取消路径，按既有资源边界清理，不能无限等待已经失效的输入窗口 |

推荐在现有窗口协作与参数状态机上补齐规则。共享部分只负责身份校验和纯判定，各组件按职责使用结果；不建立包办捕获、呈现和全局快捷键的总控制器。

## 3. 推荐的身份与状态模型

复用现有 `SourceWindowIdentity`／会话代次，分别保存捕获 HWND、已验证的 `GA_ROOT`、输出 HWND 和本会话参数宿主。`GA_ROOT` 只沿父链；不要扩大为任意同进程窗口或整条 owner 链。见 [GetAncestor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getancestor)。

每次决策先读取前台事实，并按当前有效会话分类。调用可能改变焦点、窗口关系或可见性的 USER32 API 后，重新读取事实；不能把调用前快照或 API 成功值当成最终输入所有权。

| 前台分类 | 会话与输入规则 |
| --- | --- |
| 源捕获窗口／已校验根窗口 | 属于源应用前台；无阻塞源弹窗、会话可用且有当前编辑请求时，允许尝试激活宿主 |
| 本会话参数宿主 | 会话内部前台；核实本线程焦点后才认定参数持有输入；源必须继续有效 |
| 本会话输出窗口 | 默认保持不主动激活；仅在既有有界交接期间接受临时前台，不扩大为永久有效编辑入口 |
| 经验证的真实源弹窗 | 单独处理；排除输出及其输入／边框辅助窗口。源被禁用或模态关系明确时不把它当作可抢走的参数入口，按现有弹窗／3D 规则处理输出 |
| 无关应用窗口 | 取消参数接管，保持新前台；会话是否继续沿用原窗口／全屏策略 |
| 无前台／源无效／旧会话窗口 | 无前台只是暂态，不能作为激活授权；源死亡或代次失效立即进入取消／退役规则 |

分别使用三个语义：`sourceForeground` 表示源／根真实前台，`sessionForeground` 表示当前策略接受的内部前台，`parameterInputOwned` 表示参数宿主确实持有输入。候选命名可随代码规范调整，禁止让一个 `IsFocused()` 在不同调用点继续同时表示三者。

保留对用户可见的三态；交接等待、激活失败、外部取消和退役作为内部原因／进度表达，不增加用户需要选择的状态。关闭／预览／编辑意图与宿主是否实际获得焦点分开记录。

| 转换 | 完成条件 |
| --- | --- |
| 关闭 → 编辑 | 当前用户请求有效；身份／源状态／前台复查通过；宿主激活及本线程焦点验证成功。失败则可见预览，等待下一次明确操作，不循环激活 |
| 预览 → 编辑 | 实际点击最后成功呈现的面板区域；同一次点击继续交给控件，保留现有首击语义 |
| 编辑 → 预览／关闭 | 收到退出请求后完成已接管的输入和关键队列；仍持有真实前台时才尝试返回有效源目标 |
| 编辑 → 外部取消 | 外部失焦、源模态状态或会话失效；清理本地输入与宿主，不恢复旧游戏前台，不等待失效宿主继续送消息 |
| 任意状态 → 停止／重建 | 正常活跃输入沿用完整交接；源销毁／旧会话退役走取消。输入收尾遵守已实现的 owner 解除及资源保留顺序 |

继续默认关闭；关闭时保持原鼠标交互。开启时按钮／快捷键打开即请求编辑，预览首击直接操作控件，编辑的面板外首击只负责返回游戏，Esc 逐级退出。基础修复不把“打开即编辑”改为“必须再点击一次”，不引入新的用户模式。
