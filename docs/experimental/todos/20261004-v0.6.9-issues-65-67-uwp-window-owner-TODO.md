## 2. 失败链与引入版本

检查基线 `764b04d5` 的 [ScalingWindow.cpp](../../../src/Magpie.Core/ScalingWindow.cpp) 关键路径（下述行号是修复前基线，当前分支源码行号已有变化）：

1. 第 290–303、354–367 行创建输出窗口，初始 owner 都是 `nullptr`。
2. 第 379–390 行初始化 Renderer、光标管理对象及可选触控窗口。
3. 第 392–393 行检查源窗口仍存在且未挂起。
4. 第 394–396 行调用 `SetScalingWindowOwner(Handle(), hwndSrc)`；失败即返回 `ScalingWindowCreationFailed`，对应 MP-051。
5. 第 432–443 行报告启动错误并调用 `Stop()`，销毁已经创建的输出窗口和渲染器。

附件提供的错误顺序是 owner 设置失败／87 → MP-051 → 清理阶段解除 owner 警告／1400 → 缩放结束。87 是本次提交材料里的启动触发点；后续 1400 不能反过来证明窗口在启动前已失效。前置 `IsWindow` 检查也不能完全排除随后发生的销毁竞态，实施时仍需保留这类保护。

已同时核对本地标签和 GitHub 标签指向：

| 标签 | 提交 | 与本问题相关的行为 |
| --- | --- | --- |
| `v0.6.5-experimental` | `2d37f8c0826f9b1e48d1e985d42f3cc54ff2b76c` | 创建输出窗口时传入源 HWND；没有初始化成功后显式设置 owner 并将失败升级为致命错误的分支 |
| `v0.6.6-experimental` | `9824d758b162ad3c5b5acc81e2e14c83f138e13d` | 改为初始化期间不关联 owner，初始化成功后显式设置；新增关联失败即终止启动的分支 |

引入改动见 [0.6.6 提交](https://github.com/SAOG0721/Magpie/commit/9824d758b162ad3c5b5acc81e2e14c83f138e13d) 及 [NGX 死锁保护记录](../reviews/20260906-v0.6.6-ngx-deadlock.md)。当时拆开 owner 关联的时机是为切断跨进程窗口消息等待与 SDK 初始化／关闭之间的死锁传播。本轮必须保留这项保护，不能恢复初始化前关联 owner。

此外，[ToastPage.cpp](../../../src/Magpie/ToastPage.cpp) 第 126–139 行早已有注释说明：UWP 目标可能无法建立 owner，Toast 会转入无 owner 的层级兜底。这进一步支持将 owner 关联能力与捕获能力分开处理，但 Toast 的短期置顶策略不能直接照搬到持续运行的缩放窗口。

## 3. 对附件方案的审查

附件建议“回读实际 owner”与“关联失败降级为警告”方向合理，后者是解决本次真实拒绝关联的关键。只修改 helper 的成功判断，错误 87 且关系确实未建立时仍会失败，无法单独修好 Issue 67。

当前 [ScalingWindowOwner.h](../../../src/Magpie.Core/include/ScalingWindowOwner.h) 已在调用前 `SetLastError(ERROR_SUCCESS)`，其返回值判断符合 [Microsoft 的 API 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongptrw) 所述方法。因此，不能把“忘了清 LastError”写成本次根因。附件另报成功解除关系却留下 1400 的现象，应通过实际关系回读及针对性测试验证，而非推广为所有 Windows／XAML 环境必然如此。

使用 [GetWindow 与 GW_OWNER](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow) 回读时，要保证输出 HWND 存活且为顶级窗口；子窗口没有 owner、无效句柄也可能返回空。对请求清空 owner 的情况，仅比较结果为 `nullptr` 不足以证明窗口有效。应在查询前保存调用的错误码，避免验证 API 覆盖原始诊断。

Owner 还承担层级、owner 最小化时隐藏输出、owner 销毁时的关联行为，见 [Microsoft 窗口关系说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#owned-windows)。当前 `SrcTracker::UpdateState`、`_UpdateFocusStateAsync` 和 `_CalcTopmostState` 已有显式的存活／最小化／层级管理，但无 owner 时的实际行为仍需验收，不能仅凭首帧成功就宣布修复完成。

附件 ZIP 仅含 `Magpie.exe`，没有源码补丁或构建证明。本轮只检查压缩包目录，没有解压或执行该 EXE；后续候选版应从本仓库源码构建。
