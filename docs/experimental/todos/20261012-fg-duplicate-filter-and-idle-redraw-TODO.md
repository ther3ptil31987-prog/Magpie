新增需求：减少 FG 效果器内“重复帧过滤”与帧率配置的冲突；明确视频/网页静止时的行为。用户进一步确认：**实际表现只是 FPS 降到 0，源画面恢复变化后能正常更新，不是无法恢复的卡死。** 用户指出已有“空闲重绘”应承担静止重绘职责，并要求检查 FG 将最低重绘率设为 0 的影响。

## 1. 当前结论

1. **FG 忽略了设置中的空闲最低重绘率。** 这是静止时停止内容提交、计数归零的直接因素之一，也是设置与执行不一致的问题。最低率为 0 表示“不强制产生空闲帧”，不是“把最高帧率锁为 0”；新捕获帧仍能正常处理。
2. **当前用户观察不支持卡死诊断。** 不新增“防卡死”开关，不因正常静止重启捕获或 SDK，不为数字不归零伪造新的捕获帧。
3. **单删 `useFrameGeneration ? 0` 不足以修复。** 后端和 FSR Presenter 还会阻止重复源帧推进 FG。必须把空闲的呈现重绘与新的算法输入分开。
4. **建议移除各 FG 效果器中的重复复选框，统一遵循帧率刷新策略。** 重复检测保留为通用捕获优化设置，不承担“静止时保持响应”的职责。
5. **建议让 FG 支持既有空闲重绘设置，但实现为复用稳定输出的呈现重绘。** 不重新估算光流、不重复计算 FG、不重复推进时序历史。真实输入为 0 时可以有空闲重绘，二者计数必须区分。

这项需求与[FSR3 移除 None、默认 AMDOF 质量](20261012-fsr3fg-require-optical-flow-TODO.md)并行跟踪，不以此扩大或阻塞已明确的 FSR3 运动输入修复。

## 3. 从第一性原理拆分职责

重复图像没有新增空间运动信息，但仍可能包含时间信息。捕获、算法计算、呈现和鼠标/UI 更新不必具有相同频率。

| 场景 | 正确行为 |
| --- | --- |
| 捕获到新的有效画面 | 正常计算效果/运动/FG，按真实输入时间和队列呈现 |
| 捕获到像素重复画面 | 按统一重复检测策略决定是否省去内容计算；不把过滤结果当作捕获故障 |
| 健康捕获暂时没有新帧，空闲重绘关闭 | 保持最后有效画面，继续响应鼠标/UI/停止；等待新帧 |
| 同上，空闲重绘开启 | 按配置的有效重绘率复用稳定输出进行呈现；不伪造新捕获、不重新生成运动/插帧 |
| 已有生成帧或真实帧排队 | 先正常消费完成；空闲重绘不能插队、覆盖或延迟真实内容 |
| 静止后恢复运动 | 新内容优先；根据实际间隔/会话/资源条件恢复或必要时 reset，不能反复播放静止期缓存 |
| 设备移除/明确捕获中断/真实同步超时 | 沿用故障或恢复路径，不把它伪装成“静止” |

`A A B B` 这类捕获序列也不能简单删掉重复图像后伪造时间间隔；光流帧对、真实采样时间、倍率和呈现节奏必须一致。本轮不引入猜测视频帧率或识别应用类型的新机制。

## 4. 修改方案

### 4.1 一个设置入口

- 在 DLSS / XeSS / FSR3 / Nvidia VFX VFG 的效果参数中移除 `duplicateFrameFiltering`。
- 删除 FG 对捕获重复检测的独立 override。简单模式继续使用其明确投影的策略；高级模式使用已有通用设置，不更改当前位置或存储范围。当前该值由 AppSettings 通用保存，不能宣称已经是每个配置独立存储。
- 检查 3D 模式、简单/高级模式的完整优先级，集中解析并记录最终策略及来源，不再由效果器暗中覆盖。
- 旧 FG 0/1 可能在不同效果组中互相矛盾，不能任取一组写回通用设置。迁移保留原始备份，弃用效果级字段、保持通用保存值，记录行为变化；启动、导入、复制、导出和运行中参数重启需一致且幂等。自定义效果同名参数不受影响。
- 若统一功能分阶段交付，过渡说明必须写“此效果组接管运行时重复检测，开=总是，关=关闭；不修改通用配置”，不能只注明开启覆盖。

### 4.2 空闲重绘由呈现层负责

- 继续禁止旧捕获推动新的光流/FG历史；不要直接恢复后端最低 FPS 然后把旧图像送进时序算法。
- 为呈现层增加明确的“复用稳定输出重绘”路径和空闲期限。复用已经完成并具有有效资源生命周期的输出；第一张有效输出之前不绘制未初始化纹理。
- 现有 DLSS/VFG 稳定底图路径可作为实现起点，但目前主要服务按需 UI 刷新，不能据此声称固定空闲率已经实现。
- FSR/XeSS 的 SDK 代理交换链需单独适配“不生成、只呈现”。核验其停用生成、队列排空、帧编号和恢复契约；只在进入/退出空闲阶段切换所需状态，不每次重绘切换并排空 SDK。没有完成适配的 provider 必须明确显示“暂不支持 FG 空闲重绘”，不能只重绘透明 UI 层却声称重绘了内容。
- 同一帧的采集 ID/时间戳/运动身份不因重绘改变；SDK 如需额外呈现序号，应与真实输入身份分开维护，不能伪造成捕获时刻。恢复插帧需遵循各 SDK 的历史要求。
- 空闲呈现不占用内容 FIFO，不影响真实帧的限速责任；新帧、Stop、Resize、设备错误可取消等待。保留鼠标/UI 独立刷新；重绘率遵循既有内容目标/配置上限，不能把倍率乘到空闲重绘率上。
- 这次目标是缓存图像的空闲呈现。依赖时间的动态效果有独立内容变化语义，不能把它们简单当作静态缓存，也不在本修复中无条件重跑所有前置时序效果。

### 4.3 显示准确状态

- 无内容更新且捕获没有报告错误时，显示“等待新画面”或对应说明。仅凭无回调不能肯定源程序自身没有卡住，避免把所有等待都标为“已确认静止”。
- 基础/输入计数可以为 0；空闲重绘单独计数为重绘提交，不增加真实帧或生成帧计数。工具栏可显示等待状态，详情解释“保持上一帧，新画面到来后自动继续”。
- 只有实际执行了空闲重绘才显示其测得频率；不把配置目标当作实测输出，不把提交数冒充屏幕扫描次数。FSR 输出未知的问号问题继续独立处理。
- “空闲持续重绘”的说明应覆盖 FG 实际能力；适配完成后遵循设置，未完成时明确限制，不再让设置看起来启用但被静默忽略。
