## 1. 已确认事实与证据边界

- [x] **R01** 核对微软 DXGI 文档：标准窗口／无边框 VRR 路径使用 Flip Model，创建与 Resize 保持 `DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING`，提交使用 `Present(0, DXGI_PRESENT_ALLOW_TEARING)`。该 Present flag 不能用于 `SetFullscreenState(TRUE)` 独占全屏。
- [x] **R02** 复核开发前的基线源码：`AdaptivePresenter` 的创建、Resize、Present 三处已有受 VRR 选项控制的 tearing flag；普通效果与 DLSS FG 共用此呈现路径。`XeSSFGPresenter` 的 D3D12 代理交换链也有对应判断。本分支已改为共享会话策略。
- [x] **R03** 复核开发前的基线入口：`ScalingService` 强制 `options.isVRREnabled = false`；旧全局设置字段存在，不表示缩放会启用 VRR。本分支已移除强制关闭，仅使用新的显式配置字段。
- [x] **R04** 复核窗口策略：输出使用 `WS_EX_NOACTIVATE`，意外获得前台后会恢复源窗口焦点；通常已有置顶处理。“模拟独占全屏”通过 mutex 改变通知检测状态，没有建立 DXGI 独占全屏交换链。
- [x] **R05** 核对 NoFocusLoss 固定源码 `4d30610d89a9a279aa0ef9bcfb222994e381b663`：使用 MinHook 拦截 `GetForegroundWindow`，固定返回目标进程按窗口面积选出的主窗口；拦截失焦窗口消息；失焦时让 `SetCursorPos` 返回成功而不移动光标。源码没有 `SetForegroundWindow`、`SetWindowPos` 或 G-SYNC 启用 API。
- [x] **R06** 收录用户提供的反馈：使用的第三方工具为 NoFocusLoss，反馈中看到了 NVIDIA G-SYNC 指示器。未确认注入对象、工具／Magpie 版本、操作顺序、键鼠状态、显示器实时 Hz 及实际 PresentMode；此反馈不是本会话的实机测试结果。

`CheckFeatureSupport(DXGI_FEATURE_PRESENT_ALLOW_TEARING)` 只证明应用侧 tearing 能力；创建标志、Present 成功、Independent Flip 和 NVIDIA 指示器分别提供不同层面的证据，不能单独替代显示器变频与最终显示间隔验收。

历史 r10 记录中已有显式 VRR 请求完整但未触发变频的反馈，且曾实施后撤回真实全屏焦点实验。因此，恢复开关不能直接写成“修复 G-SYNC”。暂停分支 `feature/vrr-presentation-paused`／`9176cab1` 仅作历史参考；后续实现以当前主线为基线，不整分支合入旧窗口、队列或限帧策略。

## 2. 待验证假设与实施原则

待验证假设：若 NoFocusLoss 注入 Magpie，NVIDIA 用户态驱动或 DXGI 可能读取被拦截的前台查询，把 Magpie 输出识别为适合 G-SYNC 的窗口，而 Windows 真实前台仍是游戏。也可能是失焦消息处理、两者组合或其他运行条件起作用。源码只能确认拦截行为，不能证明驱动内部调用及激活机制。

- 最新产品方向是统一的“VRR 可变刷新率”开关，标准路径与 NVIDIA 查询兼容保持分层诊断；开发入口可分别对照。全新配置默认关闭，旧双字段按新 TODO 迁移，旧隐藏全局 `vrr` 保持原迁移边界。
- 标准路径保持游戏真实前台；不把实际抢焦点、持续恢复焦点或跨进程输入队列合并作为默认方案。
- NVIDIA 兼容实验优先限定在 Magpie 自身进程，不注入源游戏；自行实现时不需要外部工具向 Magpie 注入 DLL。
- 不无条件照搬 NoFocusLoss：Magpie 的源窗口跟踪、捕获、参数宿主、快捷键和焦点恢复仍必须取得真实前台状态。
- 不预先屏蔽 `SetCursorPos` 或广泛吞掉焦点／IME 消息；只保留受控对照证实必要的最小处理。
- 首批基线为单显示器、无边框全屏、SDR、无 FG；普通窗口、FG、HDR、跨适配器及多屏逐步扩大。
- 不把 `DirectComposition` 一概判为无法 VRR；本项目 `CreateVirtualSurface`／`Commit` 路径缺少标准 DXGI 显式请求入口，首版不承诺其 VRR。实际呈现路径变化必须记录。
