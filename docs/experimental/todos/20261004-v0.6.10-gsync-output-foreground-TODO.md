# 0.6.10 G-SYNC 输出前台身份兼容 TODO

日期：2026-10-04（Asia/Shanghai）。本清单记录第一版查询兼容、真实查询隔离、生命周期、配置与参考组的源码阶段；初次开发未编译部署。后续单独会话已集成到 `0.6.10-beta2`／`96cd7b8a`，用户反馈双开关、无 FG 时输出 G-SYNC 指示器正常，DLSS／XeSS FG 均使其消失。部署日志确认目标调用命中与共同 FG 排除，当前实施顺序改由[VRR 统一入口、FG 与前台关联修正 TODO](20261004-v0.6.10-vrr-unified-fg-foreground-TODO.md)接替。见[初次实施与构建交接](../reviews/20261004-v0.6.10-gsync-foreground-source-development.md)。

工作假设：**按用户要求，先假定最终 Magpie 输出缺少前台身份就是本次 G-SYNC 不触发的根因，直接据此准备兼容实现。** 这是开发方向的假设，不把它改写成已经确认的 NVIDIA 驱动机制；不以继续穷尽其他原因作为开始开发的前置条件。

失败基线：用户测试 `0.6.10-beta1`／`e6b82596`，单屏、无 FG，控制面板“窗口和全屏模式”已开启；未看到 G-SYNC 指示器。既有日志终态为 `requested=true eligible=true creationFlags=0x840 presentFlags=0x200 reason=none`。输出使用 `WS_EX_NOACTIVATE`，意外获得真实前台后会还给源窗口。详细证据见[焦点诊断](../reviews/20261004-v0.6.10-vrr-gsync-focus-diagnosis.md)。

目标：**源游戏继续持有 Windows 真实前台、接收正常输入；在 Magpie 自身进程内，让消费前台身份的目标呈现调用看到最终输出 HWND。** 首轮优先实现仅 `GetForegroundWindow` 兼容；真实前台参考组用于验证，消息拦截按结果再加。置顶、全局还焦点和扩大 tearing flags 不作为本假设的修复入口。

最初轮次只准备 TODO；用户随后授权开始执行，源码原型在 `feature/069-vrr-gsync` 实施，并同步 Beta1 的 UWP 基线。该原型开发轮次未编译、部署、更新版本／Release 或合并主线；Beta2 集成与部署由单独会话完成。本轮再根据实验结果整理新的 TODO，未执行统一开关／FG 扩展。

关联：[VRR 总 TODO](20261004-v0.6.9-vrr-gsync-nofocusloss-TODO.md)、[标准接入记录](../reviews/20261004-v0.6.9-vrr-gsync-source-development.md)。本清单是总 TODO 的 P07、N01–N09、V07–V11 的当前优先实施顺序；最终输出预算与 FG 扩展继续保留在总 TODO。

## 3. 初始化、暂停与退出

- [ ] **K12** 已建立 device 前准备／记录及资格确认后的覆盖；早于资格确认的缓存判断尚未验证或补偿。 输出 HWND 验证完成后、Renderer／device／交换链初始化前建立准备上下文，覆盖可能缓存前台身份的创建与首次呈现阶段；只有资格已确认时才应用覆盖，首次尚不可见的输出与尚未取得的设备资格单独记录。若必要查询早于可用输出身份／资格，记录时序缺口并在明确生命周期位置处理，不能随意返回占位 HWND 或伪称覆盖了 device 初始化。
- [x] **K13** 源码阶段： 区分进程级 Hook 基础设施与会话级返回值覆盖：切屏时立刻让覆盖失效并恢复真实查询，避免每次前台变化都重装 Hook。会话状态候选为 `Preparing → Armed → Suspended / Retired`，由当前资格和真实前台决定是否应用；新会话需新 epoch。
- [x] **K14** 源码阶段： 处理 Alt+Tab、参数编辑、最小化、源弹窗、锁屏、显示器／路径变化、输出重建及停止。无关程序真实前台时不得继续返回输出 HWND，也不主动把源游戏抢回；新 HWND 验证前保持暂停，旧 epoch 的后台线程不得使用新会话身份。
- [x] **K15** 源码阶段： 停止时先撤销覆盖并退休会话，再按现有后台清理流程退出。对正在执行的 detour、真实查询和延迟后台线程明确同步策略；原始 trampoline 不得提前释放，进程级 Hook 的最终撤销不能在 `DllMain` 或 loader lock 内进行。
- [ ] **K16** 源码已有安装／启用／呈现失败锁定与禁用失败直通；外部 API 拦截冲突及实际安装撤销仍待验证。 Hook 创建／启用／撤销失败、安装冲突、无效或复用 HWND、device loss 等失败均回到真实查询及既有呈现策略；本会话锁定明确失败原因，避免每帧重装或无限重试。保留其他 Hook 的所有权，不对全进程无差别执行 enable／disable all。
