## 1. 问题与目标

当前配置页以过滤后的候选显卡数决定显卡卡片是否加载：`AdapterInfos().size() > 1`。单卡时卡片隐藏；父级“性能”分组始终显示。帧率设置迁入“帧率与刷新”后，该分组只剩显卡选择和无显卡警告，因此单卡时留下空标题。

这个功能应同时支持选择渲染设备、查看可用设备及理解设备变化后的回退。候选项只有一个时，设备信息仍有价值；“自动”和“指定该卡”也代表不同的长期选择意图。

方案目标：常驻“渲染显卡”，保留在原“性能”分组位置；单卡保留自动／指定选择；明确设备缺失时的状态；沿用现有过滤、配置匹配与运行回退策略。

## 2. 界面与交互约定

| 设备状态 | 卡片与选择 | 状态提示 |
| --- | --- | --- |
| 无候选显卡 | 卡片保留；选择控件禁用，显示“未找到可用显卡” | 提示启用效果时将尝试 CPU 渲染；创建成功前不宣称已使用 WARP |
| 一张候选显卡 | 提供“自动”和该显卡；控件可操作 | 正常状态保持简洁，无需重复解释 |
| 多张候选显卡 | 提供“自动”和各张候选显卡 | 不以厂商或型号名称代替设备身份匹配 |
| 指定显卡暂不可用，但有其他候选 | 保留指定意图，明确显示“指定显卡（暂不可用）”；用户仍可选自动或其他卡 | “指定显卡暂不可用，启用效果时将自动选择可用设备” |
| 指定显卡恢复 | 按原有配置匹配规则恢复指定选择 | 更新或清除缺失提示 |

- 卡片名称使用“渲染显卡”，与输出显示器选择区分。
- 卡片、无显卡警告和指定设备缺失提示均保留在原“性能”分组；显卡卡片始终显示，因此单卡时也不会留下空分组。
- “自动”表示由程序选择设备；“指定”表示优先使用该设备，暂不可用时回退，恢复后重新使用。
- 用户主动改成“自动”时，清除旧的指定设备 ID；临时缺失／回退时保留 ID。设备列表或绑定刷新不得被误认为用户主动修改。
- 选择控件表达保存的策略，状态文字表达缺失或回退；未启用效果时不显示“正在使用”。如后续展示实际设备，必须来自成功创建的设备，并在停止／失败后更新。

## 3. 保持的底层行为

- PR #62 的过滤继续覆盖候选列表及实际设备选择：仅在查询成功且 `IndirectDisplayDevice=1 && RenderSupported=0` 时排除该间接适配器；类型查询失败时保留原有创建与回退判断。
- 继续排除候选列表中的 WARP，保留后台 FL11 检查与设备变化后的重新枚举；WARP 仍为实际创建过程的最后回退。
- 保留原始 DXGI 索引及 `graphicsCardId.idx / vendorId / deviceId` 的配置匹配，覆盖默认配置和应用配置。
- 保留指定卡缺失时 `idx=-1`、vendor/device ID 留存及设备恢复后重匹配的行为。界面需区分该状态与三个字段均表示自动选择的状态。
- 保留当前按 DXGI 顺序尝试可创建设备的自动策略。本轮不引入性能排名、独显优先、按效果能力选卡或新的设备身份体系。
- 仅通过通用渲染能力筛选不能证明每个 NR／FG／光流效果均兼容；相关效果能力检查继续由既有路径处理。
