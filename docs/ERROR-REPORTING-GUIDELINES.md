# 错误状态与操作引导规范

适用范围：新增或修改错误状态、运行时降级、提示文案和恢复入口时按需使用。不要求其他改动执行额外流程。

## 提示应回答的问题

1. 哪个配置、效果组或效果器发生了什么？
2. 实际影响是什么：尚未启动、跳过此效果继续、整组停止，还是参数正常受限？
3. 用户现在应打开哪个真实入口、执行什么操作？
4. 怎样确认恢复？仍失败时在哪里复制诊断或打开日志？

先说明状态和影响，再说明原因和步骤。短提示保留完整的问题句；主要操作在长诊断前。技术阶段和原始码放在详情，不能要求用户自行翻译日志才能找到第一步。

## 证据与分类

- 原因由掌握失败事实的 API/后端层产生，UI 不解析英文日志作业务判断。
- 分开保存阶段、操作、原因、原始码及码类型、实际处理结果。清理失败不能覆盖首次有效失败。
- `LoadLibraryExW` 失败不证明主 DLL 缺失；先确认目标文件不存在。文件存在时保留加载或依赖问题的分类。
- NGX `FeatureNotSupported` 表示组合不支持，不单独证明显卡或 DLL 不支持。`OutOfDate` 可能涉及驱动或功能库，不直接写“驱动过旧”。
- 驱动门槛和 GPU/DLL 对应关系必须有当前发行组件的可验证规则及检测值。没有依据时保留未知，不使用历史指南的固定版本作为永久规则。
- 权限查询失败与确认目标权限更高必须分开；访问失败说明读取、写入或设备操作及对象，不默认要求管理员运行。
- 保留现有 MP 编号；新编号追加。原始 Win32、HRESULT、NGX、SEH 不混作一种系统码。

## 当前状态与恢复

- 参数受限不等于后端故障；未启用、启动中、运行中、跳过和整组停止不得混用。
- 以成功处理画面确认运行；有画面、对象存在或 Core 初始化成功都不足以证明 DLSSNR 正在处理。
- 当前状态绑定用户会话、renderer 代次和效果实例。跨线程读取快照，拒绝旧代次更新及停止后的更新。
- 最近一次问题是历史诊断，关闭提示不等于恢复。其他错误不得清除当前效果状态。
- 同一持续故障只在状态变化时通知。重试后必须有真实成功证据才显示恢复。

## 操作目标

- 能识别对象时，打开并定位该配置、效果组和效果器。目标已改变、删除或重名时说明原因并打开列表，不猜测替代对象。
- 建议符合当前配置与已知本机能力。没有已确认可用的另一张显卡时，不承诺切卡可解决；已经选择的选项不重复推荐。
- 区分重新启用效果组、完全退出并重开 Magpie、重启 Windows。只在对应路径有依据时要求较大的重启范围。
- 未知原因给有限检查和反馈出口，不堆叠管理员、换 DLL、更新驱动、关闭超频等通用尝试。
- 文件操作失败时保留可复制路径。只打开目录或说明，不自动替换用户文件。

## 本地化与验收

改动键至少提供简中、繁中、英文，检查语义和占位符；其他语言明确采用英文回退，不能保留会误导用户的旧译文。核对实际控件名称。

复用 [错误引导测试矩阵](experimental/testing/ERROR-GUIDANCE-TEST-MATRIX.md)，验证分类、真实后果、生命周期、目标变化及操作失败。源码检查、C++ 测试、产品构建、UI/DPI 和实机 GPU 验收分别记录。规范不授权编译、部署或改动用户配置。
